## 2. the WAL's cost  (insert throughput, 2000 rows)

  wal=off (bulk load)               9371 inserts/s
  wal=on  (fsync per commit)        5066 inserts/s

## 3. page size  (10000 rows, index lookup WHERE id = k)

  page   pages height  leaf/int cap  index (ms)
-----------------------------------------------
  1024     591      3         72/84       0.235
  4096     148      2       292/340       0.098
  8192      75      2       584/681       0.095

notes:
  - scan is O(rows); index lookup is ~height page reads + 1 heap read
  - the tree gains one level per ~300x more rows (fanout ~300 at 4K)
  - wal=on pays one fsync per statement - the price of durability
  - bigger pages -> higher fanout -> shorter tree, but more I/O per node
